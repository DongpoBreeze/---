- 10 张样本共产生 12 次上游请求，账本从 39 增至 51/75，剩余 24 次；目标每餐累计请求均未超过 3。由于复测开始前有些样本已经使用过请求额度，2 个后续阶段在本地额度校验处被拒绝，没有发给供应商。批次状态为 7 个超时、1 个完整响应但格式校验失败、2 个阶段额度拒绝；有 3 餐保留了至少一个完整通过校验的阶段结果。
- 最慢成功的整图请求为早餐第 4 张，80.260 秒，随后完整结果通过校验。晚餐第 3 张首轮 38.124 秒通过校验，但其局部复核等满 120 秒未完成；合并报告保留首轮结果。晚餐第 5 张两阶段分别在 101.287 秒和 25.876 秒通过校验，最终合并阶段因每餐累计额度限制未发送。其他 7 个阶段超时均是 HTTP 200、未收到 `response.completed`；晚餐第 2 张在 40.877 秒收到完整响应，但结果格式未通过校验。
- 每张照片都按照片中的整份餐食比较，不把餐前照片推算成实际摄入。10 张里只有 3 张有本轮已接受分析；只有 4 张有旧首轮基线，其中仅早餐第 4 张同时有新旧结果。由于本轮成功样本均缺少可匹配的可靠重量/食用比例，且食材烹调状态与本地目录无法可靠对应，四项营养值均按规则显示未知，没有用模型数字填补。该批照片没有称重真值，不能据此统计营养准确率。

## 本轮技术决定

- Expo SDK 57、React Native 0.86、TypeScript。Android 与 iOS 共用客户端，Web 用于快速交互验证。
- 本地记录和媒体优先保存，云端服务按需分析。原生使用 AsyncStorage 原子快照与应用私有目录；Web 使用 IndexedDB，不能代替原生可靠性测试。
- 数据模型在 `src/types.ts`，本地规则在 `src/domain.ts`。记录修订与分析版本分开；全局 `sourceVersion` 是保守的失效标记，记录或资料修改会使已有 AI 总结过期。
- AI 总结保存实际发送的资料、Markdown 输入、源记录和版本快照；训练参考依赖的历史也纳入删除和失效范围。结果在串行提交队列内核对版本、取消状态及删除代数。
- 备份使用 ZIP，包含 JSON 原始数据、CSV、Markdown、原始媒体与完整性清单；导入先校验再提交。
- 当前 App 直接连接用户填写的 HTTPS 服务，Key 在原生安全存储中独立保存，不进入健康备份。模型与推理强度来自上游元数据；未提供强度时使用服务默认。
- 历史开发网关保留 Node 24 SQLite 预算和请求指纹，模型服务密钥只在服务端。其费用预留规则不适用于用户直接调用；直接调用由用户选择的外部服务计费。
- 2026-10-10 按用户要求接入本机 Codex 的活动 Responses API，App 网关固定 `gpt-6.1-sol`、`max`；未修改 Codex 全局配置。供应商凭据在启动时用 TOML 解析器读取，只保留在服务端内存，客户端使用单独生成的开发令牌。该配置仅适用于本机开发。

## PNG HTTP 400 诊断（2026-10-10 历史记录）

旧 128×128 RGB 灰色 PNG 共 356 字节；IHDR、IDAT、IEND 的 CRC 全通过，IDAT 解压为 49,280 字节，Edge 可解码为完整灰色图。离线证据为 [PNG 校验报告](../artifacts/image-diagnostic-legacy-png-128x128-local.json)，生成函数位于 `scripts/synthetic-image.mjs`。图片损坏不是本次 400 的证据。

修复前，原 PNG 与相同 128×128 的 canvas JPEG 都返回同一上游错误：`Response input messages must contain the word 'json' in some form to use '***.format' of type 'json_object'.` 供应商的 JSON 模式只检查 `input`，旧请求仅在 `instructions` 中说明 JSON，实际输入没有明确标记。`server/protocol.mjs` 已对 Responses 的 `input_text` 加上 `JSON record:\n` 前缀，并将该错误安全分类为 `json_mode_input_missing`。旧 JPEG 成功不是格式差异的受控证据；相同尺寸 JPEG 复现同一校验错误和修复后 PNG 成功共同支持本次原因判断。

| 阶段 | 合成图 | 结果 | 诊断等待上限 | 耗时 | 证据 |
| --- | --- | --- | --- | --- | --- |
| 修复前 | 原 PNG，128×128，356 字节 | 上游 400，网关 502；缺少 JSON 输入标记 | 默认 55 秒 | 1.687 秒 | [PNG 失败报告](../artifacts/image-diagnostic-legacy-png-128x128-live.json) |
| 修复前对照 | canvas JPEG，128×128，853 字节 | 上游 400，网关 502；完全相同错误 | 默认 55 秒 | 29.443 秒 | [JPEG 失败报告](../artifacts/image-diagnostic-canvas-jpeg-128x128-live.json) |

用户附图实际为 JPEG，扩展名为 PNG；本节所述合成 PNG 诊断当时仅上传合成灰图。后续真实餐食测试已按用户要求上传指定附图，见上节。App 的分析副本继续采用 JPEG，原媒体独立保存；合成图结果不能替代食物营养准确率验收。
