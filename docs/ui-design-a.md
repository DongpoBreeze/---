# 方案 A：现行 UI 设计约定

更新日期：2026-10-22。方案 A 是本项目唯一的现行视觉方向，首次集成和 Web 验证完成于 2026-10-18；后续暗色、餐食表单和 BMI 结果展示继续沿用这一设计底座。文档分工与证据入口见 [文档索引](README.md)。

## 目标与范围

将 `health-compass-test` 中已选定的方案 A 应用到本项目的真实 Expo App。今天页沿用方案 A 的信息顺序、24 格节律矩阵、同排记录按钮、营养汇总与健康总结；其他页面及表单统一使用相同的色彩、卡片和排版约定。

底部为“今天、趋势、我的、设置”四个 Tab（记录为“我的”下的子页面），以及饮食、训练、睡眠的新增、编辑、删除、草稿、本地持久化、媒体、营养参考与数量换算、分析历史、每日总结、个人资料、AI 服务设置、数据导出恢复等能力。数据 schema、AI 请求协议和营养计算规则遵循现有产品与营养规格；本文件维护视觉约定，后续业务变化以对应规格为准。

### BMI 结果展示（2026-10-22）

参考用户提供的网页 BMI 计算器截图优化信息层级：以大号 BMI 数值和状态为主，旁边显示按身高计算的正常体重参考。四档横线展示偏瘦、正常、超重和肥胖，各档显示当前身高对应的公斤分界；“你”和“目标”标记分层呈现，同一位置时也可区分。下方并列展示阶段体重及每日热量建议，详细计算规则继续折叠。

宽卡片采用结果与刻度左右布局，手机窄屏上下排列；范围标签按可用宽度换行，标记文字不越过刻度边缘。四段为分类示意，边界仍对应中国成人 BMI 18.5、24、28，各段内的位置按比例换算；它不表示四段有相同的 BMI 跨度。四档公斤分界是显示约数，实际分类使用未取整 BMI。

缺少有效身高时只展示 BMI 分类，不生成公斤分界；缺少有效身高或体重时保留待补充。当前/目标数值与无障碍标签沿用同一临界值格式函数。随后用户确认增加选填性别及年龄：资料表单提供“暂不填写／男／女”和周岁输入，按年龄即时展示未成年、成人或老年组别；未填年龄标明普通成人参考，已知非普通成人或年龄无效时保留 BMI 数值并说明需分龄解读，不渲染成人目标刻度和自动建议。英制输入及参考图中的数值不作为业务常量。此次按用户要求仅更新并验证网页版，不新建 APK；验证结果见 [开发记录](development.md#profile-health)。

## 真实数据与状态

- 今日条数、已记天数、训练与睡眠汇总根据保存的记录计算；空白页面明确说明可以记录什么。
- 营养汇总保留热量及蛋白质、碳水、脂肪的真实区间、来源和数据完整性。未知值显示“未知”或占位符，不能因界面布局而填成零。
- 每 100 g 参考与用户实际摄入分开呈现；没有数量时不计入摄入，部分填写、参考过期及历史兼容状态继续准确显示。规则见 [营养实现规格](nutrition-implementation.md)。
- AI 区分未配置、待记录、处理中、成功、过期、失败与取消，保留手动触发和取消入口；本地反馈标明来源。自动打开页面不触发 AI，不将参考稿文案当成已经完成分析的证据。
- 原始记录、媒体、分析版本与备份完整性保持既有规则。AI 设置与凭据继续独立于健康备份，服务能力和费用说明遵循 [用户 AI 设置约定](user-ai-settings.md)。
